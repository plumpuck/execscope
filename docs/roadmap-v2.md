# ExecScope v2：机构级路线（草案，待确认数据源）

目标：不是“能跑的演示”，而是一个机构里的执行分析 / 量化开发团队看得懂、信得过、能接着用的工具。
机构级 = 方法严谨 + 可复现 + 可验证 + 可解释 + 工程规范，不是功能多。

## 一、分析方法（机构 TCA 的核心）
| 模块 | 内容 | 为什么机构要这个 |
|---|---|---|
| 基准体系 | 到达价、决策价、区间 VWAP、收盘价、TWAP 基准、前一日收盘 | 不同基准回答不同问题，报告要同时给出 |
| Implementation Shortfall 分解 | 延迟成本 + 执行成本 + 机会成本（未成交部分）+ 费用 | 业界标准（Perold）；区分“慢了多少”和“冲击了多少” |
| 市场冲击模型 | 平方根冲击模型，用数据校准参数；临时冲击 vs 永久冲击 | 事前成本估计、对默认成交模型做基准 |
| 事前成本估计 | 下单前预测成本与风险（Almgren-Chriss） | 机构在下单前就要知道预期成本 |
| 算法族 | TWAP、VWAP（历史成交量曲线）、POV、IS（Almgren-Chriss 最优轨迹）、收盘算法 | 对照不同场景的取舍，不是只有一个 |
| 统计严谨性 | 大量父单、分层（大小/时段/波动率）、bootstrap 置信区间、显著性检验 | 一次回测的差异可能只是噪音 |

## 二、回测保真度（我们项目的独特角度）
| 实验 | 问题 |
|---|---|
| E1 | 拆单（TWAP/VWAP/POV/IS）相对一次性下单，成本差多少，置信区间是多少 |
| E2 | 成交模型、延迟、队列位置设置，如何改变成本估计 |
| E3 | 默认成交模型对大单成本的低估量（对平方根冲击基准） |
| E4 | K 线 vs 逐笔/盘口数据：数据粒度本身带来的偏差 |
| E5 | 参数敏感性与稳健性：结论在不同时段、不同波动率下是否成立 |

## 三、数据与参考实现
- 数据：需要逐笔成交 + 盘口（L2）才能谈机构级。候选：Databento（有免费额度，机构常用）、币安公开 L2/逐笔（免费）、CME 样本。**数据源选哪个会改变后续全部设计，需用户确认。**
- 数据质量层：时间戳校验、乱序/重复/缺口检测、异常值、合约换月处理。
- 参考实现：Python（numba）撮合模拟器，用于验证 Nautilus 的结果；C++ 版本作为性能对照（可选）。

## 四、工程规范
- 配置化实验（YAML）、固定随机种子、结果可复现（同一配置得到同一结果，记录版本与数据哈希）。
- 测试金字塔：单元测试 + 属性测试（hypothesis）+ 回归测试（黄金结果）；覆盖率；类型检查（mypy）；lint（ruff）；CI（GitHub Actions）。
- 包结构：src 布局、可安装、CLI 入口；不再是散落脚本。
- 可观测：结构化日志、每次实验输出报告（HTML/PDF）。
- 服务层：FastAPI + PostgreSQL/DuckDB 存实验与成交，Docker Compose 一键启动，仪表板。
- AI 层（可选）：自动生成 TCA 报告解读，每个数字有来源校验，不能编造。

## 五、合规视角（HK/SG 机构语境）
最佳执行（best execution）要求有据可查：报告要能回答“为什么选这个算法、成本多少、相对哪个基准”。输出格式向券商 TCA 报告看齐。

## 六、分级交付（避免做不完）
- Tier 1（基础可信）：基准体系 + IS 分解 + TWAP/VWAP/POV + E1/E3 + 单元/回归测试 + 包结构 + 可复现。
- Tier 2（机构方法）：平方根冲击校准 + Almgren-Chriss + 统计检验 + E2/E5 + 数据质量层 + CI。
- Tier 3（接近产品）：逐笔/L2 数据 + 参考撮合模拟器 + E4 + 服务层 + 仪表板 + AI 解读。
时间：原计划 2 周只够 Tier 1 的一部分；机构级整体需要重估（预计数周），需用户确认可投入时间。
